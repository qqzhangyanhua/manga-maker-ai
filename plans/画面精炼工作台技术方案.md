# 画面精炼工作台技术方案

## 背景与目标
- **问题**：当前生成后的图片无法直接在站内继续加工，用户对不满意的作品只能反复重新生成，效率低下。
- **目标**：提供“图片 → 页面”的完整处理体验，打通入口、版本管理、AI 优化与分格/气泡编辑能力，支持手动上传素材复用。

## 用户流程
1. **入口**：首页新增「画面精炼中心」卡片，展示最近一次生成的缩略图与 CTA；在生成器结果区域提供“继续精炼”按钮，自动带入刚生成的图片。
2. **作品聚合**：进入工作台后加载所有生成/上传的版本（任务状态、来源、时间等）。
3. **优化模式选择**：
   - 原图 AI 优化：选择风格模板及强度，提交后进入异步任务，完成后写入新版本，可快速对比与回退。
   - 漫画分格 + 气泡拖拽：Fabric.js（默认）或 Konva.js（后续可切换）提供画布，每个分格/气泡可自由拖拽、缩放、编辑文本，并支持预设分格模板。
4. **手动上传**：任何时间都能导入本地图片作为新的版本来源。
5. **导出与复用**：支持导出整页 PNG、分格 JSON（结构化保存）以及继续回到分镜/工作流中使用。

## 页面信息架构
- **工作台头部**：展示当前版本、来源、修改状态以及快捷切换。
- **左侧侧栏**：
  - “AI 调优”Tab：风格/强度选择、额外 prompt、消耗提示、任务进度。
  - “分格与气泡”Tab：模板库、面板/气泡新增按钮、吸附/对齐开关、导出按钮。
  - “素材”Tab：手动上传、资产库引用入口。
  - 底部版本时间线：列出所有版本，支持标记状态、重命名、删除。
- **右侧画布**：Fabric.js 实例包含背景图、分格矩形、气泡文本、辅助栅格，提供撤销/重做、缩放等操作。

## 数据与接口
- **版本模型**（后端：可扩展 ProjectAsset 表 or 新建 ImagePageVersion）：
  - `id`, `projectId`, `sourceType`（generation/upload/optimization/layout）、`imageUrl`, `meta`（JSON，包含 prompt、模板、画布 schema 等）、`status`、`createdAt`.
- **API**：
  1. `POST /api/image/optimize`：参数 `{imageUrl, prompt, mode, strength}` → 生成任务 → 返回 `taskId`。
  2. `GET /api/image/page/[id]`：获取指定作品的版本列表及分格 schema。
  3. `POST /api/image/page`：保存 Fabric schema/导出任务（后续）。
  4. 复用 `GET /api/image/task-status` 轮询任务进度。
- **Fabric Schema**：
  - `panels: { id, x, y, w, h, angle }[]`
  - `bubbles: { id, text, x, y, w, h, style }[]`
  - `background: { imageUrl, scale, offset }`

## 前端技术方案
- 新增 `src/app/editor/page.tsx` 作为入口页面，支持查询参数 `image`（从生成器或历史记录带入）；
- 编写 `ImageEditorWorkspace` 组件封装工作台布局，左右分栏，右侧 Fabric 画布；
- `useFabricCanvas` Hook 统一管理 Fabric 初始化、背景图载入、模板套用、对象分类与导出；
- 版本时间线/操作面板拆分为可复用组件（VersionList、ActionSidebar 等），互通当前版本状态；
- 首页 `GeneratorSection` 增加“继续精炼”入口，并通过 `image` query 传递最新生成图；
- Header 导航新增“画面精炼”菜单，确保随处可达。

## 后端扩展
- 在 `src/app/api/image` 下新增 `optimize` route，复用 `generateImage` 队列，将 mode/strength 传入 metadata，后续可基于 metadata 决定调用的模型或后处理；
- 为 Fabric 分格数据准备存储接口（本阶段只保存在客户端，下一阶段再写入数据库，保持 schema 前置设计）；
- 上传仍复用 MinIO 流程：前端通过 `/api/upload/presign` 获取 URL，当前阶段允许直接 DataURL 预览，后续再替换为真实对象。

## 任务拆分
1. **体验与页面骨架**：新增首页入口、导航、编辑页面布局与版本面板；
2. **Fabric 画布能力**：初始化画布、加载背景、模板（两列、三宫格等）、气泡组件、导出；
3. **AI 优化接口**：`/api/image/optimize` + 前端轮询封装，写入版本栈；
4. **上传与版本管理**：本地上传、版本状态标记、回退与设置为当前工作图；
5. **数据持久化与发布**（下一阶段）：与 Prisma 模型对齐，接入资产库和导出保存。

## 风险与建议
- Fabric SSR 不可用，所有相关代码需在客户端组件内动态加载；
- AI 优化需要配合计费与风控，metadata 中应带上来源与用户 ID；
- 分格 schema 需提前约定，避免后续数据迁移困难；
- 注意导出时的跨域问题（需确保背景图允许 CORS 访问），可以统一走 MinIO 私有读取再签名。
