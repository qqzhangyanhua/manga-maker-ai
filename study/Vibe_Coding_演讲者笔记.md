## 💡 演讲技巧提示

### 开场（0-2 分钟）
**目标：** 建立共鸣，吸引注意力

**话术模板：**
> "请举手：有多少人经历过改一行代码，等编译30秒，刷新页面，状态丢失，又要重新操作？"
>
> （观察举手人数）
>
> "看来大家都深有体会。今天我要分享的 Vibe Coding，就是为了让这种痛苦成为历史。"

**注意事项：**
- 语速适中，不要急
- 眼神接触，扫视全场
- 微笑，展现自信

---

### Demo 演示（7-19 分钟）
**目标：** 震撼观众，展示实际效果

**Demo 1: 从零到运行（5分钟）**
```bash
# 提前准备好这些命令（复制到剪贴板）
pnpm create vite vibe-demo --template react-ts
cd vibe-demo && pnpm install && pnpm dev
```

**口述要点：**
- "注意看时间，我现在开始计时"（夸张时间对比）
- "浏览器自动打开了，不到2秒冷启动"（强调速度）
- "现在我修改代码，注意右边的浏览器"（同时操作）
- "看，不到50毫秒就更新了，状态还保持着"（指向屏幕）

**失败应对：**
- 如果网络慢：立即切换到备用项目
- 如果报错：使用录屏视频，顺带讲解错误处理

### MCP 讲解（19-27 分钟）
**目标：** 让观众理解 MCP 的革命性价值

**类比话术：**
> "MCP 就像 USB 协议。以前每个设备都要专门的驱动，现在插上就能用。MCP 让 AI 访问工具也是同样道理。"

**Auggie MCP 演示要点：**
- 先展示传统 `grep -r "auth"` 的噪音结果（1000+ 行）
- 再展示 Auggie 的精准结果（8 个文件）
- 对比强烈，视觉冲击

**口述模板：**
> "传统方式，grep 找到 1000 多个结果，我需要 10 分钟人工筛选。Auggie MCP 3 秒返回 8 个精准结果，准确率 98%。这就是语义理解的力量。"

---

### Skill 讲解（27-35 分钟）
**目标：** 让观众看到工作流自动化的潜力

**/commit Skill 演示：**
1. 先展示手写 commit message 的痛苦（不知道写什么）
2. 输入 `/commit`
3. AI 自动分析改动 + 学习风格 + 生成消息
4. 结果展示（规范、清晰、风格统一）

**口述模板：**
> "以前我纠结 10 分钟，到底写 'fix bug' 还是写一段长篇大论。现在 `/commit`，5 秒搞定，还自动学习项目风格。"

- 重点：Claude 主控 + 代码主权

## 📝 Q&A 准备

### 预期高频问题

**Q: 这些工具学习成本高吗？**
A: 基础使用 0 学习成本。Vite 开箱即用，MCP 一次配置永久有效，Skill 就是输入命令。高级定制才需要学习，但有完整文档。

**Q: 公司项目能用吗？有安全问题吗？**
A: 完全可以。MCP 提供权限隔离，Skill 可以审计日志。代码主权在你手上，AI 只是建议。敏感项目可以用私有部署的 MCP。

**Q: Codex/Gemini 是什么？怎么接入？**
A: 这是我的自定义工作流，调用了 Google Codex CLI 和 Gemini CLI。你可以根据自己习惯替换成其他工具，核心是多模型协作的思路。

**Q: 这套流程适合小团队吗？**
A: 非常适合！小团队人力有限，更需要效率工具。一个人顶三个人用，性价比极高。我们 3 人团队用这套流程，产出抵得上 10 人传统团队。

**Q: 会不会让初学者变懒，基础变差？**
A: 恰恰相反。AI 生成的代码是学习材料。你可以研究它的实现，学习最佳实践。就像有了计算器，数学家反而能专注更高级的问题。关键是理解代码，不是盲目复制。

**Q: 投资回报率真的有 1000% 吗？**
A: 保守估计。假设工具成本 $20/月，每周节省 10 小时，按时薪 $50 算，每月节省 $2000。ROI = 2000/20 = 100倍 = 10000%。实际可能更高。
