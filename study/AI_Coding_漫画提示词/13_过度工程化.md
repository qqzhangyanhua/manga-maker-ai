# 13 过度工程化

**模式：场景对比** - 简单需求 vs 复杂实现

四格漫画竖版布局，标题在漫画顶部居中，风格简洁、幽默、清晰易懂，所有人物均以卡通风格表现，适合用于网络传播。

---

## 标题（居中）：
**《AI Coding 陷阱：一行需求，两百行代码》**（中文，加粗）

---

## 第一格（完整横格）：
- **场景**：用户和 AI 的对话界面。
- **用户消息**（简单明了）："帮我写一个读取 config.json 的函数"
- **用户内心期望（虚线气泡）**：
  ```javascript
  const config = JSON.parse(fs.readFileSync('config.json'))
  ```
  "应该就一两行吧？"

---

## 第二格（完整横格）：
- **场景**：AI 回复界面，滚动条很长，代码密密麻麻。
- **AI 回复**（代码预览，用小字表示很长）：
  ```
  class ConfigManager {
    private static instance: ConfigManager;
    private config: Map<string, any>;
    private observers: Observer[];
    private validators: Validator[];
    private cache: LRUCache;
    private hotReloadWatcher: FileWatcher;
    // ... 200 行代码
  }
  ```
- **用户表情**：震惊，眼睛睁大

---

## 第三格（完整横格）：
- **场景**：用户呆坐在电脑前，周围堆满了各种设计模式的图表（单例模式、观察者模式、工厂模式...），都是 AI 在代码里用到的。
- **用户内心独白**："我只是想读个配置文件啊..."
- **屏幕旁边的便利贴**：
  - "需求：1 行"
  - "AI 输出：200 行"
  - "过度设计：19900%"

---

## 第四格（完整横格）：
- **场景**：左右对比
- **左半边 - 小刚（接受过度设计）**：
  - 小刚把 200 行代码全部复制到项目
  - 三个月后：代码变得无法维护，小刚抱头
  - 标注："过度复杂，维护噩梦"
- **右半边 - 小红（要求精简）**：
  - 小红对 AI 说："请精简到最小实现，不需要缓存和热重载"
  - 屏幕显示简洁的 3 行代码
  - 标注："够用就好，简洁即美"
- **底部总结**："告诉 AI：最小化改动，不要过度设计"

---

## 附加风格要求：
- 第二格的"超长代码"视觉效果是重点，可以用滚动条暗示代码很长。
- 第三格的设计模式图表要夸张，形成"信息轰炸"效果。
- 对比的数字（1 行 vs 200 行）要醒目。
