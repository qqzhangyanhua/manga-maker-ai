# 16 Skill 协作的安全机制

**模式：场景对比（Split Screen）**

四格漫画竖版布局，标题在漫画顶部居中，风格简洁、清晰易懂，通过对比展示外部模型的零写入权限和 Claude 主控机制，所有元素均以卡通风格表现，适合用于网络传播。

---

## 标题（居中）：
**《Skill 协作：零写入权限 + Claude 主权》**（中文，加粗）

---

## 第一格（完整横格）：
- **场景**：权限架构展示
- **画面布局**：金字塔式权限结构

### 顶部 - Claude（主控层）：
- **Claude 形象**：
  - 站在金字塔顶端，穿着"Orchestrator"指挥服
  - 手持权限令牌（钥匙 🔑）
  - 表情：专业、负责
- **权限标识**（绿色盾牌）：
  ```
  ✅ 读取权限
  ✅ 写入权限
  ✅ 执行权限
  ✅ 主控决策
  ```
- **对话气泡**："我是主控，拥有所有权限！"

### 中间 - 外部 Skills（协作层）：
- **Codex 和 Gemini 形象**：
  - 站在金字塔中层
  - 手持"只读证件"
  - 表情：专业但受限
- **权限标识**（黄色警告）：
  ```
  ✅ 读取权限
  ❌ 写入权限（严禁）
  ❌ 执行权限（严禁）
  ⚠️ 仅生成建议
  ```
- **对话气泡（Codex）**："我们只能生成 Diff，不能改文件！"
- **对话气泡（Gemini）**："所有建议都要 Claude 审核！"

### 底部 - 文件系统（保护层）：
- **图标**：🔒 文件系统（上锁状态）
- **标注**："外部模型无法直接访问"

### 安全机制说明（底部文字框）：
**"强制约束：Codex/Gemini 对文件系统零写入权限"**

---

## 第二格（完整横格）：
- **场景**：外部 Skills 的工作方式
- **画面布局**：工作流程图

### Codex 的工作台（左侧）：
- **画面**：
  - Codex 坐在"代码分析台"前
  - 屏幕显示代码阅读界面（只读模式）
  - 右侧有"生成 Diff"的编辑器
- **工作流程**（用箭头展示）：
  ```
  1. 读取代码（只读） 📖
     ↓
  2. 分析逻辑 🧠
     ↓
  3. 生成 Diff Patch 📝
     ↓
  4. 输出给 Claude ✉️
  ```
- **屏幕显示（Diff 输出）**：
  ```diff
  OUTPUT: Unified Diff Patch ONLY

  --- a/src/auth.ts
  +++ b/src/auth.ts
  @@ -10,5 +10,12 @@
  +export function validateToken() {
  +  // 新增函数逻辑
  +}
  ```
- **红色警告框**（强制提示）：
  ```
  ⚠️ SYSTEM_CONSTRAINT:
  "Strictly PROHIBIT file modifications.
   You MUST NOT write to filesystem.
   OUTPUT: Unified Diff Patch ONLY."
  ```

### Gemini 的工作台（右侧）：
- **画面**：
  - Gemini 坐在"设计分析台"前
  - 屏幕显示 UI 组件代码（只读模式）
  - 右侧有"生成 UI Diff"的编辑器
- **工作流程**（用箭头展示）：
  ```
  1. 读取 UI 代码（只读） 📖
     ↓
  2. 分析设计 🎨
     ↓
  3. 生成 UI Diff 📝
     ↓
  4. 输出给 Claude ✉️
  ```
- **屏幕显示（Diff 输出）**：
  ```diff
  OUTPUT: Unified Diff Patch ONLY

  --- a/src/Button.tsx
  +++ b/src/Button.tsx
  @@ -5,3 +5,8 @@
  +<Button
  +  variant="primary"
  +  size="large"
  +/>
  ```
- **红色警告框**（强制提示）：
  ```
  ⚠️ SYSTEM_CONSTRAINT:
  同上
  ```

### 底部标注：
**"外部 Skills 生成'脏原型'（Dirty Prototype）"**

## 第三格（完整横格）：
- **场景**：Claude 主控的工作流程
- **画面布局**：Claude 的"思维沙箱"

### Claude 的工作流程（用流程图展示）：

#### Step 1 - 读取 Diff（顶部左）：
- **图标**：📥 接收
- **画面**：
  - Claude 接收来自 Codex 和 Gemini 的 Diff
  - 屏幕显示两个 Diff 文件（叠放）
- **标注**："接收外部建议"

#### Step 2 - 思维沙箱模拟（顶部右）：
- **图标**：🧠 模拟
- **画面**：
  - Claude 的"大脑"可视化（透明脑袋，里面有代码流动）
  - 模拟应用 Diff 的效果
  - 思考气泡：
    ```
    🤔 如果应用这个 Diff...
    - 逻辑是否正确？
    - 类型是否安全？
    - 是否有副作用？
    ```
- **标注**："在思维沙箱中模拟"

#### Step 3 - 检查 + 重构（中间左）：
- **图标**：🔍 审查
- **画面**：
  - Claude 手持放大镜检查代码
  - 屏幕显示审查清单：
    ```
    ✓ 逻辑检查
    ✓ 类型安全检查（禁用 any）
    ✓ 文件行数检查（< 500 行）
    ✓ 代码规范检查
    ✓ Linus "好品味"标准
    ```
- **标注**："按 Linus 标准重构"

#### Step 4 - 最终实施（中间右）：
- **图标**：⚙️ 实施
- **画面**：
  - Claude 手持"写入权限钥匙"🔑
  - 屏幕显示文件修改操作：
    ```
    Writing to filesystem...
    ✓ src/auth.ts (updated)
    ✓ src/Button.tsx (updated)
    ✓ All changes applied
    ```
- **标注**："Claude 主控实施"

### 底部安全保障标注：
**"只有 Claude 有写入权限，确保代码主权"**

---

## 第四格（完整横格）：
- **场景**：对比总结 + 价值展示
- **画面布局**：左右对比 + 底部价值

### 左半边 - 不安全方式（灰色调，带 ❌）：
- **标题**："如果外部模型有写入权限..."
- **问题场景**：
  - Codex 直接修改文件（红色警告）
  - Gemini 直接修改文件（红色警告）
  - 文件系统混乱：多个 AI 同时写入
  - 冲突图标：⚠️ 文件冲突
- **风险列表**（红色）：
  - ❌ 代码质量无法保障
  - ❌ 可能覆盖重要代码
  - ❌ 无法审查和回滚
  - ❌ 失去代码主权
- **标注**："混乱且危险"

### 右半边 - Claude 主权方式（绿色调，带 ✅）：
- **标题**："零写入权限 + Claude 主控"
- **安全流程**：
  - 外部模型：生成 Diff（只读）
  - Claude：审查 + 重构
  - Claude：最终实施（写入）
  - 结果：代码质量有保障
- **优势列表**（绿色）：
  - ✓ 代码质量一致（Claude 标准）
  - ✓ 可审查、可回滚
  - ✓ 保持代码主权
  - ✓ 安全可控
- **标注**："安全且可控"

### 底部价值总结区域：
- **大字标题**（加粗）：
  **"外部模型只生成 Diff，Claude 主控实施"**
  **"代码主权 = 安全可控"**

- **三大核心价值**（用图标强调）：
  - 🛡️ **零写入安全**：外部模型无法直接修改文件
  - 👑 **Claude 主权**：最终决策和实施由 Claude 控制
  - 🔍 **质量保障**：所有建议必须经过 Claude 审查和重构

## 附加风格要求：
- 第一格的金字塔权限结构要清晰：用颜色区分层级（绿色 > 黄色 > 灰色）
- 第二格的红色警告框要醒目："STRICTLY PROHIBIT"要用大写加粗
- 第三格的 Claude 工作流程要详细：4 个步骤用箭头连接
- 第四格左右对比要强烈：混乱危险（红色 ❌）vs 安全可控（绿色 ✅）
- 外部模型的"只读证件"和 Claude 的"写入钥匙"要视觉化
- 整体风格：安全感 + 专业感，像安全架构文档
- 特效使用：🔑 钥匙、🔒 锁、🛡️ 盾牌，强调安全机制
