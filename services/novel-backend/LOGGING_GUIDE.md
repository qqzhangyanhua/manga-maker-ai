# LLM 提示词日志记录指南

## 概述

为了方便调试和审查，我们在所有 LLM 调用点添加了完整的提示词日志记录。

## 日志位置

日志输出到 Python 后端的标准日志系统（`logging`）。

### 查看实时日志

**开发环境**:
```bash
cd services/novel-backend
# 启动后端服务（如果还没启动）
uvicorn app.main:app --reload --log-level info

进程内测试不需要先启动服务：在本目录 `pip install -r requirements-dev.txt` 后执行 `pytest`。

# 或者查看日志文件（如果配置了文件日志）
tail -f logs/app.log
```

**生产环境**:
```bash
# Docker 容器日志
docker logs -f novel-backend

# 或使用日志聚合工具（如 CloudWatch, ELK 等）
```

## 日志字段说明

| 字段 | 说明 |
|------|------|
| `章节号` | 当前生成的章节编号 |
| `system_prompt 长度` | 系统提示词的字符数 |
| `user_prompt 长度` | 用户提示词的字符数 |
| `context 长度` | 上下文（世界观、角色等）的字符数 |
| `max_tokens` | 最大生成 token 数 |
| `temperature` | 温度参数（控制随机性） |
| `model` | 使用的 AI 模型 |

## 如何使用日志

### 调试提示词

1. **检查提示词长度**:
   - 如果 `user_prompt 长度` 过大（>10000 字符），可能导致 token 超限
   - 建议优化上下文构建逻辑

2. **审查提示词内容**:
   - 检查系统提示词是否包含正确的写作规则
   - 确认用户提示词是否包含必要的上下文信息

3. **分析生成质量问题**:
   - 如果生成内容字数不足，检查提示词中的字数要求是否清晰
   - 如果生成内容偏离大纲，检查提示词中的约束是否足够明确

### 性能优化

1. **Token 使用分析**:
   ```bash
   # 统计 token 使用情况
   grep "max_tokens" logs/app.log | grep "章节生成"
   ```

2. **平均响应时间**:
   ```bash
   # 查看章节生成耗时
   grep "✅ 章节生成成功" logs/app.log
   ```

### 问题排查

1. **生成失败**:
   ```bash
   # 查看错误日志
   grep "ERROR" logs/app.log | grep "生成失败"
   ```

2. **字数不足**:
   ```bash
   # 查看字数警告
   grep "⚠️ 章节字数不足警告" logs/app.log
   ```

## 日志级别配置

**开发环境** (推荐 `INFO` 级别):
```python
# services/novel-backend/app/main.py
logging.basicConfig(level=logging.INFO)
```

**生产环境** (建议 `WARNING` 级别，按需调整):
```python
# 如果需要调试，临时调整为 INFO
logging.basicConfig(level=logging.INFO)

# 正常运行时使用 WARNING
logging.basicConfig(level=logging.WARNING)
```

## 注意事项

⚠️ **隐私保护**:
- 提示词日志可能包含用户的故事内容和角色设定
- 生产环境应确保日志文件安全存储，避免泄露用户数据
- 建议配置日志轮转和自动清理策略

⚠️ **存储空间**:
- 完整的提示词日志会占用较大存储空间
- 建议配置日志轮转（如每天轮转，保留 7 天）
- 可在生产环境中只记录 prompt 长度，不记录完整内容

## 示例：日志轮转配置

```python
# services/novel-backend/app/main.py
import logging
from logging.handlers import RotatingFileHandler

# 配置文件日志（10MB 轮转，保留 5 个备份）
handler = RotatingFileHandler(
    'logs/app.log',
    maxBytes=10*1024*1024,  # 10MB
    backupCount=5
)
handler.setFormatter(logging.Formatter(
    '%(asctime)s - %(name)s - %(levelname)s - %(message)s'
))
logger = logging.getLogger()
logger.addHandler(handler)
logger.setLevel(logging.INFO)
```
