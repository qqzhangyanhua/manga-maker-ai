# P0 - 新手引导与一键体验功能设计

## 一、问题诊断

### 1.1 核心问题

当前产品存在严重的**认知负荷过载**问题：

| 问题 | 现状 | 影响 |
|------|------|------|
| 入口分散 | 6个创作相关页面（story/scripts/workflow/editor/storyboard/projects） | 新用户迷失，不知从何开始 |
| 路径混乱 | 4条并行创作路径，无明确推荐 | 决策疲劳，放弃尝试 |
| 首页欺骗 | "生成漫画"按钮为占位，选择风格/角色后无下文 | 用户期望落空，信任受损 |
| 引导缺失 | 无新手教程、无示例项目、无流程指引 | 首次用户直接流失 |

### 1.2 用户痛点验证

```
用户视角：
1. 进入首页 → 看到漂亮的界面和多个按钮
2. 选择漫画风格 → 选择角色类型 → 填写描述
3. 点击"生成漫画" → 什么都没发生（或跳到复杂页面）
4. 困惑 → 尝试其他入口 → 更加迷失
5. 放弃 → 离开

这是典型的"功能丰富但不可用"问题。
```

### 1.3 Linus 式判断

**核心判断：** 这是个真问题，直接影响用户留存。

**关键洞察：**
- 数据结构：用户需要一个清晰的"任务流"，而不是"功能菜单"
- 复杂度：6个入口可以收敛为1个主流程 + 3个快捷入口
- 风险点：不能破坏现有用户的工作流习惯

---

## 二、设计方案

### 2.1 功能概述

实现两个核心功能：

| 功能 | 目标 | 用户价值 |
|------|------|----------|
| **创作流程可视化** | 让用户5秒内理解"该怎么做" | 降低认知负荷，提升转化 |
| **一键体验（试一试）** | 0注册即可体验核心价值 | 证明产品能力，提升注册转化 |

## 四、功能二：一键体验（试一试）

### 4.1 设计目标

- 用户无需注册，30秒内看到 AI 生成的漫画效果
- 证明产品核心价值，提升注册转化
- 限制免费体验次数，引导注册

### 4.2 用户流程

```
用户进入首页
    ↓
点击"试一试"按钮
    ↓
弹出体验对话框
    ↓
输入一句话描述（如："一个程序员加班到深夜的故事"）
    ↓
选择漫画风格（可选，默认日式）
    ↓
点击"生成预览"
    ↓

    ↓
展示 4 格漫画预览
    ↓
┌─────────────────────────────┐
│  喜欢这个效果？              │
│  注册账号保存作品并继续编辑   │
│                             │
│  [注册保存]  [再试一次]      │
└─────────────────────────────┘
```

### 4.3 技术方案

#### 4.3.1 API 设计

```typescript
// POST /api/trial/generate
// 无需认证，但有频率限制

interface TrialGenerateRequest {
  prompt: string;           // 用户输入的一句话描述
  style?: string;           // 漫画风格 ID（可选）
  fingerprint: string;      // 浏览器指纹（用于限流）
}

interface TrialGenerateResponse {
  success: boolean;
  panels: {
    order: number;
    description: string;    // 分镜描述
    imageUrl: string;       // 生成的图片 URL
  }[];
  remainingTrials: number;  // 剩余体验次数
  trialId: string;          // 用于注册后关联
}
```

#### 4.3.2 后端处理流程

```
接收请求
    ↓
检查频率限制（每 IP 每天 3 次）
    ↓
调用 LLM 将一句话扩展为 4 格分镜描述
    ↓
并行调用图像生成 API 生成 4 张图片
    ↓
临时存储结果（Redis，24小时过期）
    ↓
返回预览结果
```

#### 4.3.3 频率限制策略

| 维度 | 限制 | 说明 |
|------|------|------|
| IP | 3次/天 | 基础限制 |
| 浏览器指纹 | 3次/天 | 防止换 IP 绕过 |
| 全局 | 1000次/天 | 成本控制 |

#### 4.3.4 数据存储

```typescript
// 临时存储体验结果（Redis）
interface TrialResult {
  id: string;
  prompt: string;
  style: string;
  panels: Panel[];
  createdAt: Date;
  fingerprint: string;
  claimed: boolean;  // 是否已被用户认领
}

// 用户注册后关联
// 将 trialId 关联到新用户，转换为正式 Story + Panels
```

### 4.5 注册后关联

当用户注册后：

1. 检查 localStorage 中的 `trialId`
2. 调用 `POST /api/trial/claim` 关联到用户账号
3. 自动创建 Story + Panels
4. 跳转到 `/scripts/[storyId]` 继续编辑

## 七、技术风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 图像生成 API 不稳定 | 体验功能不可用 | 准备降级方案（返回占位图 + 文字描述） |
| 滥用体验功能 | 成本超支 | 严格的频率限制 + 全局配额 |
| 体验效果不佳 | 转化率低 | 优化 prompt 模板 + 精选风格 |
